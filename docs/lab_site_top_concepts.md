# 研究室サイト トップ表現の検討メモ

- 作成日: 2026-10-03
- ステータス: 表現の比較用プロトタイプを作成。要件は未定
- プロトタイプ: `lab-site/top-concepts/index.html`(ブラウザで直接開ける。外部依存は Google Fonts のみ)

## 1. 方針

- トップのヒーローは、アニメーションに見せかけた演出ではなく **実際の計算をそのまま描く**。研究室の扱う手法そのものを見せる
- 画面下に **ライブキャプション** を置き、いま何を計算しているかを1行で示す。説明がないと「きれいな点と線」で終わるのを防ぐ
- 触ると計算の入力が変わり、結果が組み直される(クリック1回で分かる程度の操作に絞る)
- 止まった1枚(サムネイル、動きを減らす設定)でも成立させる。`prefers-reduced-motion` のときは収束後の状態で静止する

## 2. 3案

| | A 探索の波 | B 学習する境界 | C つながりが学ぶ |
|---|---|---|---|
| 主なテーマ | グラフ理論 | 機械学習 | ネットワーク × グラフ × 学習 |
| 伝わること | 最短経路が近い順に確定していく。1回の実行で全頂点への最短路が求まる | データから学ぶ過程そのもの | 少数のラベルが辺を伝って広がり、ネットワーク全体の構造を推定する |
| 中で動く計算 | ランダム点のガブリエルグラフ、速さの違う辺、ダイクストラ法 | 2-16-16-1 のニューラルネットを Adam で学習。決定境界をマーチングスクエアで描画 | 確率的ブロックモデルのネットワーク、力学モデル配置、ラベル伝播法(Zhou et al., 2004) |
| 触ったとき | クリック地点から再探索。ホバーでその頂点への最短路 | クリックで予測と逆のラベルの点を追加 | クリックした頂点のラベルを切替。ホバーで隣接頂点を強調 |
| 負荷 | 軽い | 中(毎フレーム数千点の推論) | 軽い〜中(130頂点まで) |
| 懸念 | 学習の要素が見えない | TensorFlow Playground に似る。グラフ要素がない | 説明がないと伝わらない |

A は既存の「配達員ダイクストラ」(`docs/dijkstra_game_design.md`)と同じ見せ方(確定時の波紋、フロンティアの強調、距離の色分け)をとっており、教材への導線にできる。

## 3. 推し

**C をトップのヒーローにし、A と B は研究テーマ紹介のセクションで使う。**

C は3テーマ(構造としてのグラフ、伝わるネットワーク、推定する学習)が1つの動きの中で説明できる唯一の案。A と B は単独テーマの見出し背景として役割を分ける。

## 4. 発展案

- C のネットワークを研究室の実データにする(論文の共著・引用ネットワーク、メンバーと研究テーマの二部グラフなど)
- スクロールに合わせて C → A → B と計算が切り替わり、各研究テーマの説明につながる
- ライブキャプションを全ページ共通の意匠にする

## 5. 要件で決めること

- 研究室名、キャッチコピー(プロトタイプの文言は仮)
- 主な閲覧環境(スマホの比率)、明暗どちらを基本にするか
- トップの役割(ヒーローのみか、研究紹介まで担うか)
- 実データを使うか。使うならデータの更新方法
- サイトの置き場所と構成(静的サイトか、既存の基盤 `docs/requirements.md` と関係させるか)
