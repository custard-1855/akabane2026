# 研究室サイト トップ表現の検討メモ

- 作成日: 2026-10-03(同日改訂: 第一印象を優先する方針に変更)
- ステータス: トップの表現はC-5(有名なグラフ)に決定(2026-10-03)。要件は未定
- プロトタイプ: `lab-site/prototypes/top-concepts/index.html`(ブラウザで直接開ける。外部依存はGoogle Fontsのみ)

## 1. 方針

- トップのヒーローは **パッと見て「いいな」と思えること**を最優先にする。アルゴリズムの説明や指標の表示は載せない
- 研究テーマ(グラフ理論・機械学習・ネットワーク)は、雰囲気として伝われば十分とする
- 光る線と点、奥行き、ゆっくり続く動きで見せる。クリックすると少し反応する程度の操作に留める
- `prefers-reduced-motion` のときは止まった1枚で表示する

## 2. 3案

| 案 | 元にしたテーマ | 見え方 | 印象 |
|---|---|---|---|
| A 光の枝 | グラフ理論 | 点のあいだを光が枝分かれしながら広がり、余韻を残して消える | 静かで知的 |
| B 流れる境界 | 機械学習 | 二色の境目と等高線が液体のようにうねり続ける | やわらかく有機的 |
| C 伝わる星座 | ネットワーク | 回転する立体のネットワークを色の信号が駆けめぐる | 華やかで奥行きがある |

裏ではAは最短経路探索、Bは小さなニューラルネットの学習、Cはネットワーク上の伝播を実際に計算しているが、画面上では説明しない。

- 主な閲覧環境(スマホの比率)、明暗どちらを基本にするか

## 4. 実データをもとにした試作(2026-10-03 追加)

プロトタイプ: `lab-site/prototypes/top-concepts/topologies.html`。C案(立体で信号が伝わる)の見せ方をもとに、形を実データや実在のグラフで決めた。

| 案 | 形 | データ |
|---|---|---|
| C-1 航空路線 | 回る地球儀の上に、路線数の多い300空港と1,262路線(各空港につき航空会社の多い路線を5本まで)を大円の弧で描く | OpenFlights(ODbL、2014年時点)、Natural Earth(パブリックドメイン) |
| C-5 有名なグラフ | C60フラーレン → トーラス → 6次元超立方体 → ジオデシック球の順に、16秒ごとに切り替え。信号は控えめ | 計算で生成 |
| NN ニューラルネット | 3Blue1Brown風の見た目で、ページ内の計算を1手ずつ実行して見せる。演出(加速・減速、残光)は入れず、1手 = 1拍(0.08秒)で再生する | scikit-learn digitsで実際に学習した重み(テスト正解率97%) |

- NNの1手の内訳(実際の処理順)
  1. 8×8の画像を行優先で一列に並べる(1行 = 1手)
  2. 入力を上から順に見て、0でない入力 `a[i]` ごとに、`z[j] += a[i] × W[i][j]` を全ニューロンへ一度に足す(1入力 = 1手)。各ニューロンの下のゲージは、途中までの合計を示す
  3. バイアスを足す → シグモイド(出力層はソフトマックス)で出力を決める(各1手)
  4. 3層ぶん繰り返し、0〜9の確率を棒で示す
- データは `tools/build_data.py` で `data/*.js` に変換している(numpyとscikit-learnが必要)。元データの取得先はスクリプト冒頭に記載
- 不採用: A-2 東京の鉄道、A-5 ケーニヒスベルクの七つの橋
- 保留: A-1 大学周辺の道路網(場所が未定。OpenStreetMapからの取得が必要)

## 5. 決定: C-5 有名なグラフ(2026-10-03)

トップのヒーローはC-5 にする。比較用のタブや操作ボタンを外した単独版を `lab-site/index.html` に置いた(外部依存はGoogle Fontsのみ)。

- 形: C60フラーレン → トーラス → 6次元超立方体 → ジオデシック球の順に、16秒ごとに切り替える。右下に形の名前を小さく表示
- 動き: ゆっくり回転し、2.4秒ごとにどこかの頂点から色の信号が出て、辺を伝って枝分かれする
- 操作(2026-10-03 改訂)
  - ドラッグで回す。手を離すと慣性で少し回り、やがて自動回転に戻る。スマホは横になぞると回る(縦はページのスクロール)
  - ホバー: カーソルに一番近い頂点と、その隣の頂点・辺を照らす(マウスのみ)
  - クリック/タップ: その頂点から、表示中の形に割り当てた処理を実際に実行する(2026-10-06 改訂、9章)
  - 触っている間と探索の波が出ている間は、形を切り替えない(最後の操作から4秒たつと再開)
- 動きを減らす設定: 信号が広がった状態の1枚で止める。ドラッグで向きを変えられ、クリックすると探索の結果(探索木)をまとめて表示する
- 調整用の値(回転の速さ、信号の間隔や数など)はファイル内の `CFG` にまとめた
- 比較用の試作(`lab-site/prototypes/top-concepts/`)は記録として残す

## 6. クリックの処理と配色の比較(2026-10-06)

比較ページ: `lab-site/prototypes/hero-variants.html`。採用版と同じヒーローの下に切り替えボタンを置き、組み合わせを試せるようにした(選択は端末に保存)。どの処理もクリックした頂点から実際に実行し、起きた順に再生する。

| 処理 | 見え方 |
|---|---|
| 幅優先探索(現行) | 近い順に1ホップずつ波のように広がり、全体を覆う木になる |
| 深さ優先探索 | 1本の線が行けるところまで伸び、行き止まりで戻って別の道へ進む |
| 最も遠い点への最短路 | 一番遠い点までの道を1本だけ引く。静かで線が少ない |
| 最小全域木(クラスカル法) | 短い辺から順に選び、あちこちの小さな木がつながって1本になる。クリックした場所には依存しない |
| ランダムウォーク | 光の点がでたらめに歩き、通った跡が少しずつ消える |
| 貪欲彩色 | 近い順に、隣と違う色で頂点を塗る。C60とトーラスは3色、超立方体は2色で塗り分けられる |

| 配色 | 中身 |
|---|---|
| 5色(現行) | 青・橙・緑・赤・紫。華やかだが、意味のない色の違いが多い |
| 2色 | 常時の信号は青、クリックした処理は橙。色で「誰が起こしたか」が分かる |
| 1系統 | 青から白へのグラデーション。処理の進み具合を明るさで表す |
| 単色 | 青のみ。もっとも落ち着くが、彩色の処理は色の区別がつかない |

## 7. 配色の決定と彩色の追加(2026-10-06)

- ブランドカラーは青。配色は2色を基本とし、常時の信号は青、クリックで起こした処理は橙(先頭ほど明るい)にする。採用版 `lab-site/index.html` に反映済み
- 彩色の処理だけ、塗り分けの色を最大7色まで使う(青・橙・緑・赤・紫・水色・黄)。ぶつかった所や失敗の印は白(明るい画面では濃紺)
- 比較ページ `lab-site/prototypes/hero-variants.html` の処理を「探索」5種と「彩色」4種に整理し、実行結果を一行で表示する

| 彩色の処理 | 中身 | 結果(C60 / トーラス / 超立方体 / ジオデシック球) |
|---|---|---|
| 貪欲彩色 | 近い順に、使える色のうち番号が一番小さい色で塗る | 3〜4色 / 4色 / 2色 / 5色 |
| 3色の塗り分け | 選べる色が一番少ない頂点から塗り(DSatur)、行き詰まったら戻って塗り直す(バックトラック)。3色で無理なら4色 | 3色 / 3色 / 2色 / 3色は不可 → 4色 |
| 2色の塗り分け | 二部グラフの判定。同じ色がつながったら、原因の奇数の輪を示して止まる | 5本の輪で不可 / 11本の輪で不可 / 2色 / 3本の輪で不可 |
| 辺の塗り分け | 1点に集まる辺がすべて違う色になるよう辺を塗る。集まる辺の最大本数と同じ色数を試し、試行回数が多すぎたら1色増やす | 3色 / 4〜5色 / 6色 / 6〜7色 |

- ジオデシック球は次数5の頂点を含む三角形分割のため、3色では塗れない(実際に探索して確かめる)。4色定理により4色では必ず塗れる
- 試行回数には上限を設け、再生は5〜6秒前後に収まるよう1手の長さを調整する

## 8. 処理の絞り込みと採用版への組み込み(2026-10-06)

- 残す処理: 幅優先探索と、彩色4種(貪欲彩色・3色の塗り分け・2色の塗り分け・辺の塗り分け)。深さ優先探索・最遠点への最短路・最小全域木・ランダムウォークは外した
- 辺の塗り分けは、線を半透明(不透明度0.42)でやや細く塗り、形が透けて見えるようにした
- 採用版 `lab-site/index.html` に5つの処理をすべて組み込み、クリックするたびに順番に切り替える。実行中は右下の形の名前の横に処理の名前を出し、終わると消す(結果の文は出さない)
- 比較ページ `lab-site/prototypes/hero-variants.html` は、残した5つを選んで試せる形にし、結果の文も表示する

## 9. 形ごとの処理の割り当て(2026-10-06)

採用版のクリックの処理は、形ごとにその特徴がよく見えるものを1つずつ割り当てる。

| 形 | 処理 | 理由 |
|---|---|---|
| C60フラーレン | 辺の塗り分け | 辺がちょうど3色で塗り分けられる |
| トーラス | 幅優先探索 | 波が輪を回り込み、反対側でぶつかる |
| 6次元超立方体 | 2色の塗り分け | 4つの形の中で唯一、2色で塗れる(二部グラフ) |
| ジオデシック球 | 3色の塗り分け | 3色では塗れないと分かり、4色で塗り直す |

- 貪欲彩色はヒーローでは使わない(比較ページには残す)
- 塗り分けの色は、常時の信号の青と混ざらないよう、橙・緑・赤・紫・水色・黄・青の順に使う

## 10. テーマの手動切り替えと検証用の図形切り替え(2026-10-06)

- テーマ: ヒーロー右上のボタンで「自動」「ライト」「ダーク」を順に切り替える。「自動」は端末の設定(prefers-color-scheme)に従う。選択は端末に保存し、次に開いたときも使う。採用版と比較ページの両方に置いた
- 図形(検証用): ヒーローのすぐ下に「自動」「C60フラーレン」「トーラス」「6次元超立方体」「ジオデシック球」のボタンを置いた。形を選ぶとその形で固定し、「自動」で16秒ごとの切り替えに戻る。公開時は `.dev` の要素ごと外す

## 11. 公開の準備: 試作の凍結(2026-10-06)

- サイトはGitHub Pagesで公開する。公開するのは採用版のヒーロー(`lab-site/index.html`)だけにする
- 比較用の試作は `lab-site/prototypes/` に移して凍結する。ビルドと公開の対象にせず、作り直しもしない(検討の記録として残す)
  - `prototypes/top-concepts/`: トップ表現の3案と、実データの3案(2〜4章)
  - `prototypes/hero-variants.html`: クリックの処理と配色の比較ページ(6〜8章)
- 作り直しの前に、今の実装に対するテストを用意した(`lab-site/README.md`)
  - 処理のテスト: 形の頂点数・辺数・次数、幅優先探索の正しさ、彩色の結果が正しい塗り分けになっているか、2色の判定で示す奇数の輪の長さ(C60は5、トーラスは11、ジオデシック球は3)
  - ブラウザのテスト: 乱数と時間を固定したcanvasの絵の比較と、操作の挙動
  - 分かったこと: ジオデシック球の4色の塗り分けは、開始点によっては試行回数の上限(6000)で打ち切られる(162頂点のうち14頂点を開始点にした場合)。実装は別の開始点で最大3回やり直すので、実際に塗り残すことはまずない
  - 既知の不具合: 動きを減らす設定で検証用のボタンから形を選ぶと、フェードインが進まず何も描かれない

## 12. TypeScriptへの移行とファイル分割(2026-10-06)

- `lab-site/` をVite + TypeScriptにし、1ファイルだったヒーローを役割ごとのモジュールに分けた(構成は `lab-site/README.md`)
- 処理は変えていない。11章のテストが分割後のビルドでもすべて通ることを確認した(canvasの絵も画素単位で一致)
- 検証用の図形切り替えは、開発サーバーかURLに `?dev` を付けたときだけ出す(10章の「公開時は外す」を自動にした)
- テストで分かったこと: 辺の塗り分けの結果の文は「試した色数」を出す。最大次数の色数での試行が打ち切られて1色増やすと、実際には増やす前の色数で塗れていても多い方を報告する(ヒーローでは結果の文を出さないので見た目には影響しない)
