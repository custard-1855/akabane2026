# ゲーム案と全ゲームに共通する方針

- 作成日: 2026-10-21。配達員ダイクストラの設計書の 1.1(ゲーム案の一覧)と 1.2(全ゲームに共通する方針)をここへ移し、ゲーム案を見直して、残した3本の初期仕様を書いた
- ステータス: 初期仕様 / 3本の試作を `prototypes/` に作った(2026-10-21)。遊んで確かめるのはこれから
- 用語: `GLOSSARY.md`
- 関連: 配達員ダイクストラの設計書 `docs/dijkstra_game_design.md`、実装方針 `docs/implementation_policy.md`
- 作業の一覧: `docs/games_todo.md`

この文書には、ゲーム案の一覧、全ゲームに共通する方針、各ゲーム案の初期仕様を書く。初期仕様は1本あたり1ページ程度とし、学習目標、共通の2段の実現、試作のステージ、ゲームの言葉と正式な用語の対応までを決める。データ構造・画面・テスト計画は、展示物にすると決まったときに、ゲームごとの設計書(`docs/<名前>_game_design.md`)を作って詰める。

## 2. 全ゲームに共通する方針

2本目以降で作り直しにならないよう、次の点は全ゲームで共通にする。

| 項目 | 方針 |
|---|---|
| プレイヤー | グラフ理論を知らない中高生から一般の来場者まで。1人が1台で5〜10分遊ぶ |
| 実行環境 | ブラウザで動かし、HTML・CSS・JSで表現する。バックエンドはDjango。端末は貸与の ASUS Chromebook C425(14型・1920×1080・タッチ対応、横画面) |
| 遊び方 | 「自分で解く → アルゴリズムの解と比べる」の2段を必須とする。アルゴリズムの自動実行(観戦)とCPUとの対決は、ゲームごとの任意機能とする。試作の3本は、どれも自動実行を層Bとして置く |
| 採点 | ゲームごとに決める。最適解があるゲームでは最適解との差で評価する |
| ステージ構成 | 小さいグラフで直感をつかみ、最後に大きいグラフで「人間には無理だがアルゴリズムなら一瞬」を見せる |
| 用語 | プレイ中はゲームの言葉(交差点・道など)だけを使う。クリア後の解説で、頂点・辺・重みなどの正式な用語と結びつける |
| 舞台 | 全ゲームが「街」を舞台にし、題材は通信ネットワークにつながるものにする。遊ぶほど街ができていく、といったゲームどうしの統合はしない |
| グラフデータ | 配達員ダイクストラと同じ形(設計書 3.3)で持つ |

- **2段を必須にし、採点をゲームごとにする理由**: 「自分でやってみてから、アルゴリズムのやり方を見る」順番は、配達員ダイクストラで確かめた体験の芯なので残す。一方、「最適解との差」は最適化問題に特有の採点で、全ゲームに課すと題材を狭めてしまう。電波技師ウェルシュでは、アルゴリズム(貪欲法)が最適とは限らず、人間が勝てる場合がある。それ自体を学習目標にする(5章)。
- **題材を通信にする理由**: 川原研究室の研究対象は通信ネットワークで、特設サイトの展示紹介でも「グラフから通信ネットワークへのつながり」を書く。題材が通信なら、解説からそのままつなげられる。
- **道は共通の言葉にする**: 配達員ダイクストラと工事士クラスカルでは、2つの地点を結ぶものをどちらも「道」と呼ぶ(`GLOSSARY.md`)。2本を遊んだ人に、ゲームが変わってもグラフという同じ構造だと伝わるようにするためである。

## 3. 試作

ゲーム案が面白いかを確かめるために、1ステージだけ作って遊べるようにする。作り直す前提とし、展示物にするかは遊んでから決める。

### 3.1 期限・順番・置き場所

- 期限: 2026-10-27〜10-30。配達員ダイクストラの最終版(10/26)の後に作る。
- 順番: 工事士クラスカル → 電波技師ウェルシュ → 回線係フォード。期限までに全部できなければ、後ろから削る。
  - 工事士クラスカルは、地図の描画、道のタップ、合計の表示を配達員ダイクストラからいちばん流用できるので先にする。
  - 回線係フォードは、層Bの付け替えの見せ方が難しいので最後にする。
- 置き場所: `prototypes/<名前>/`。展示物にすると決まったら `apps/` へ移す。どれが展示物かを、ディレクトリで分かるようにするためである。
- 作り方は実装方針(1〜3章)に従う。ビルドなしの静的ファイルとし、計算はDOMに依存しないファイルに置いて `node --test` でテストする。
- 配達員ダイクストラの表示部品と `tokens.css`・フォントはコピーして使い、共通のモジュールには切り出さない。共通にするのは、展示物にすると決まってからにする。

### 3.2 範囲

| 含める | 含めない |
|---|---|
| 1ステージの層Aと層B、星、ゴースト(自分の答えに最適解を重ねる)、1手戻る・リセット、配達員ダイクストラと同じ見た目 | タイトル画面、案内、ヒント、星の保存、解説の本文(用語の対応表を1枚出すだけにする) |

### 3.3 確かめること

試作を遊んで、次の点を確かめる。展示物にするかは、この結果を見て決める。

| ゲーム | 確かめること |
|---|---|
| 工事士クラスカル | 層Aで、輪を作ったり高い道を選んだりして、最小を逃す人がいるか。層Bの「輪になるので飛ばす」が見て伝わるか |
| 電波技師ウェルシュ | 層Aで、最小のチャンネル数まで減らそうと粘るか。層Bで、順番を変えるだけで数が変わることに驚くか |
| 回線係フォード | 層Aで、まだ増やせるのに行き詰まる人が多いか。層Bの付け替えが見て分かるか |

## 4. 工事士クラスカル

### 4.1 題材

街の局舎どうしを、道に沿って光ファイバーでつなぐ。道ごとに工事費がかかる。直接つながっていなくても、全部の局舎が通信できれば完成とし、工事費の合計をできるだけ小さくする。通信網を最小のコストで張る問題そのものである。

### 4.2 学習目標

| # | 学習目標 | 体験させる場所 |
|---|---|---|
| 1 | 全部がつながれば十分で、輪を作るのは無駄 | 層A。輪ができたら「1本外しても全部つながっています」と知らせる |
| 2 | 安い順に、輪にならない道だけを敷けば最小になる | 層B。安い順に道を光らせ、敷くか、輪になるので飛ばすかを字幕で出す |
| 3 | 目先で安い道を選ぶやり方(貪欲法)は、配達員ダイクストラの Stage 2 では損をしたが、ここでは最適になる | 解説。2本を遊んだ人だけが得る気づきとする |

### 4.3 層A(自分で解く)

1. 地図に局舎と道を出す。道には工事費が書いてある。
2. 道をタップすると敷き、もう一度タップすると外す。工事費の合計を常に出す。
3. 輪ができても禁止しない。輪になった道を強調し、「1本外しても全部つながっています」と知らせる。
4. 全部の局舎がつながったら「完成」を押せる。押すと星が付き、最小の敷き方をゴーストとして重ねる。

### 4.4 層B(アルゴリズムと比べる)

クラスカル法を自動で進める。道を工事費の安い順に1本ずつ光らせ、輪にならなければ敷き、輪になるなら飛ばす。字幕は「いちばん安い道 X(n万円)を敷く」「X を敷くと輪になるので飛ばす」の形にする。

- プリム法ではなくクラスカル法にする。プリム法は1点から広げていくので、見た目がダイクストラ法の波紋とほぼ同じになる。クラスカル法の「安い順に見て、輪になるなら飛ばす」は見た目がはっきり違い、学習目標2をそのまま見せられる。

### 4.5 採点

最小の工事費との差で評価する。★3は最小と同じ、★2は `star2` 以下、★1はそれ以外とする(配達員ダイクストラと同じ形)。`star2` は地図を作るときに決める。

### 4.6 試作のステージ

- 局舎は8〜10個、道は14〜16本にする。
- 工事費を道の長さに比例させない。比例させると、目で見るだけで答えが分かる(配達員ダイクストラの設計書 2.1 と同じ理由)。
- 工事費はすべて違う値にする。最小の敷き方が1つに決まり、層Bで安い順が同点にならない。
- 安い道だけで輪ができる箇所を1つ以上置く。層Bで「飛ばす」が起きるようにするためである。
- 見た目は真ん中を通る幹線に見えるが、工事費が高い道を1本置く。その道を使うと★2以下になるようにする。配達員ダイクストラの目先の罠と同じく、見た目で選ぶと損をする瞬間を作る。

### 4.7 ゲームの言葉と正式な用語

| ゲームの言葉 | 正式な用語 |
|---|---|
| 局舎 | 頂点 |
| 道 | 辺 |
| 工事費 | 重み |
| 敷く | 辺を選ぶ |
| 輪 | 閉路 |
| 全部つながって輪がない敷き方 | 全域木 |
| 工事費が最小の敷き方 | 最小全域木 |
| 層Bの手順 | クラスカル法(1956年) |
| 安い道から選ぶやり方 | 貪欲法 |

## 5. 電波技師ウェルシュ

### 5.1 題材

街の基地局に無線のチャンネルを割り当てる。電波が届き合う隣どうしの基地局が同じチャンネルを使うと混信する。混信をなくしたうえで、使うチャンネルの数をできるだけ少なくする。無線の周波数割り当てそのものである。

### 5.2 学習目標

| # | 学習目標 | 体験させる場所 |
|---|---|---|
| 1 | 隣どうしは違うチャンネルにする、という制約 | 層A。混信している組を赤で示す |
| 2 | 順に「使える中でいちばん小さい番号」を付けていくやり方(貪欲法)は、塗る順番によってチャンネルを余計に使う | 層B。順番を変えて2回動かす |
| 3 | 最小の数を確かめるには、ほぼ全部の組み合わせを試すしかない | 解説 |

- このゲームでは、アルゴリズムが最適とは限らない。層Bの貪欲法に人間が勝てる場合があり、それ自体が学習目標2・3の体験になる(2章の採点の方針)。

### 5.3 層A(自分で解く)

1. 地図に基地局と、隣どうしを結ぶ線を出す。
2. 基地局をタップすると、チャンネルが順に変わる。チャンネルは色と番号の両方で示す(色覚多様性への配慮)。
3. 混信している隣どうしの線を赤で示す。
4. 混信がなくなったら「完成」を押せる。押すと、使ったチャンネルの数で星が付く。

### 5.4 層B(アルゴリズムと比べる)

貪欲法を自動で2回動かす。各回とも、決まった順番で基地局を1つずつ光らせ、隣が使っていない中でいちばん小さい番号を付ける。

1. 1回目: 地図の左から右へ、のような自然に見える順番で塗る。最小より多いチャンネルを使う。
2. 2回目: 隣どうしの多い基地局から塗る(ウェルシュ–パウエル法)。最小の数で済む。

2回の結果と、自分の答えを並べて見せる。

### 5.5 採点

最小のチャンネル数(彩色数)との差で評価する。最小の数は、小さい地図なので総当たりで求める。`star2` は地図を作るときに決める。

### 5.6 試作のステージ

- 基地局は8〜10個にする。最小のチャンネル数は3とする。
- 層Bの1回目(自然に見える順番)の貪欲法では4つ以上使い、2回目(隣どうしの多い順)では3つで済むようにする。
- 1回目の順番は、適当に並べた順ではなく、自然に見える順番にする。「自然な順番で塗ったら余計に使った」ほうが、順番で結果が変わることに気づきやすく、驚きも大きい。

### 5.7 ゲームの言葉と正式な用語

| ゲームの言葉 | 正式な用語 |
|---|---|
| 基地局 | 頂点 |
| 隣どうし | 辺(隣接) |
| チャンネル | 色 |
| 混信 | 隣接する頂点が同じ色 |
| 混信のない割り当て | 彩色 |
| 必要なチャンネルの最小の数 | 彩色数 |
| いちばん小さい番号から付けるやり方 | 貪欲法 |
| 隣どうしの多い順に塗るやり方 | ウェルシュ–パウエル法(1967年) |
| 最小を確かめるには全部試すしかないこと | NP困難 |

## 6. 回線係フォード

### 6.1 題材

データセンターから街の端の利用者へ、回線を通してデータを送る。回線ごとに帯域(一度に送れる量の上限)があり、向きが決まっている。全体で一度にどれだけ送れるかを求める。

### 6.2 学習目標

| # | 学習目標 | 体験させる場所 |
|---|---|---|
| 1 | 先に決めた送り方を後から付け替えると、全体の量を増やせることがある | 層Aで行き詰まり、層Bで付け替えを見る |
| 2 | 全体の量は、街を2つに分ける切れ目のうち、いちばん細い所の帯域の合計で決まる | 層Bの最後に、いちばん細い切れ目を太線で示す |

### 6.3 層A(自分で解く)

1. 地図にデータセンター(S)、利用者(T)、回線を出す。回線には帯域と、今の送る量が書いてある。
2. S から T へ、回線の向きに沿って地点を順にタップし、ルートを作る。帯域が残っていない回線は通れない。
3. T に着くと、そのルートで送れるだけ(途中の回線の残りのうち、いちばん少ない量)を送る。
4. 送る向きは回線の向きだけとし、付け替えはできない。送り方によっては、まだ増やせるのに行き詰まる。
5. 1手戻る(最後に送ったルートを取り消す)とリセットでやり直せる。S から T へのルートがもうなければ「完成」とし、送れた量で星が付く。

### 6.4 層B(アルゴリズムと比べる)

フォード–ファルカーソン法を自動で進める。ルートを1本ずつ見つけて送り、順方向のルートがなくなったら、付け替え(すでに送っている分を逆向きに取り消して、別のルートに回す)で量を増やす。終わったら、いちばん細い切れ目を太線で示し、その帯域の合計が送れた量と等しいことを字幕で出す。

- 付け替えの描き方は、試作で確かめる(7章)。

### 6.5 採点

送れる量の最大との差で評価する。`star2` は地図を作るときに決める。

### 6.6 試作のステージ

- 地点は6〜8個にする。
- S から T へのいちばん短い(通る回線が少ない)ルートで最初に送ると、その後は順方向のルートがなくなり、最大より少ない量で行き詰まる。誰でも最初にやる手を罠にする、配達員ダイクストラの目先の罠と同じ構図である。
- 別の順番で送れば、付け替えなしでも最大に届く。層Aで★3を取れる送り方を残すためである。
- 最大の量に対応する切れ目は1か所に決まるようにする。

### 6.7 ゲームの言葉と正式な用語

| ゲームの言葉 | 正式な用語 |
|---|---|
| データセンター | 始点 s |
| 利用者 | 終点 t |
| 回線 | 有向辺 |
| 帯域 | 容量 |
| 送る量 | 流量 |
| 一度に送れる量の最大 | 最大流 |
| 付け替え | 残余グラフの逆辺を使うこと |
| 切れ目 | カット |
| いちばん細い切れ目と最大が等しいこと | 最大流最小カット定理 |
| 層Bの手順 | フォード–ファルカーソン法(1956年) |
