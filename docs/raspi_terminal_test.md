# Raspberry Pi 端末動作テスト 手順書

最終更新: 2026-09-29

## 1. 目的・スコープ

Raspberry Piにモニタとマウスをつなぎ、端末としてアプリ(`apps/dijkstra-delivery`)を遊べるかを確認する。Piをサーバ側に使う構成(要件整理 8章)は扱わない。

基盤サーバ(`src/`)は未実装のため、アプリの静的ファイルを `python3 -m http.server` で配信して代用する。

- ES Modulesを使うため、`file://` では動かない。HTTPで配信する。
- `index.html` が読み込む `/core/sdk.js` は404になる。`core-adapter.js` はsdkがなければ何もしないため、動作に影響しない。
- 入力は `click` のみで、ホバーに依存する操作はない。マウスで操作できる。

## 2. 準備物

| 項目 | 内容 |
|---|---|
| 本体 | Raspberry Pi 4 または 5。Pi 3以前・ZeroはChromiumの動作が重い |
| 電源 | Pi 5は27W(5V/5A)、Pi 4は15WのUSB-C電源。容量不足は動作不安定の原因になる |
| 映像ケーブル | micro-HDMI → HDMI のケーブルまたは変換アダプタ(Pi 4/5の端子はmicro-HDMI) |
| microSD | 16GB以上 |
| 入力機器 | USBマウス。初回設定用にUSBキーボード |
| モニタ | HDMI入力のもの |
| ネットワーク | MacとPiが同一LANにあること |

## 3. Piのセットアップ

1. Macに Raspberry Pi Imager を入れ、microSDに **Raspberry Pi OS(デスクトップ版)** を書き込む。
2. 書き込み時の設定画面で、ユーザ名・パスワード、Wi-Fi、ロケール(タイムゾーン・キーボード配列)を入力しておく。初回起動時の入力が減る。
3. microSD、モニタ、マウス、キーボードをPiにつなぎ、最後に電源をつなぐ。
4. デスクトップが表示されたら、Chromiumが起動できることを確認する。Raspberry Pi OS(デスクトップ版)には標準で入っている。

## 4. アプリの配信

### Macから配信する場合(本番構成に近い)

1. MacのIPを確認する。
   ```
   ipconfig getifaddr en0
   ```
2. 静的ファイルを配信する。
   ```
   cd apps/dijkstra-delivery/static
   python3 -m http.server 3000 --bind 0.0.0.0
   ```
3. macOSのファイアウォールのダイアログが出たら、Pythonの受信を許可する。
4. PiのChromiumで `http://<MacのIP>:3000/` を開く。
   - 要件整理 7章に合わせ、`.local` ではなくIP指定で開く。

### Pi単体で配信する場合

Macを使わずに試す場合は、`static/` をPiにコピーし、Pi上で同じコマンドを実行して `http://localhost:3000/` を開く。

## 5. 確認項目

| 項目 | 確認内容 |
|---|---|
| 表示 | 画面が表示され、コンソールに `/core/sdk.js` の404以外のエラーがない |
| 描画性能 | SVGのアニメーションがカクつかない。Macより性能が低いため、最も重点的に見る |
| レイアウト | モニタの解像度・横向きで崩れない。F11で全画面にした場合も確認する |
| マウス操作 | ノードやボタンのクリック判定が小さすぎない |
| ステージ操作 | ステージ選択、モード切替、元に戻す、リセット、ヒントが動く |
| 終了 | 終了ボタンで `/` に移動する。この構成では `/` が `index.html` のため、ゲームが再読み込みされる |

コンソールはChromiumで `Ctrl+Shift+J` を押して開く。
